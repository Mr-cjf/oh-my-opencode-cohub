# 上下文效率

> **规范源**: 团队 AI 协作约定（工具无关）
> **同步规则**: 规范源 checklist 更新时，本文件同步更新。

## 执行清单

> AI 协作时的效率约束。

- [ ] 所有任务必须先 Plan Mode 规划再执行（小任务可简化计划但不跳过）
- [ ] 复杂任务避免把上下文窗口用到最后 20%（容易跑偏/遗忘/输出退化）
- [ ] 多文件并行修改时，独立文件尽量并行操作（最大化工具调用并行度）
- [ ] 编译/测试等长时间任务使用 `run_in_background`（不阻塞主流程）
- [ ] 避免用 Bash 做文件搜索/读取（优先使用 Glob/Grep/Read 专用工具）
- [ ] 3 个以上独立探索任务使用 Agent 并行派发（而非串行探索）

---

## 工具选择优先级

| 场景 | 优先使用 | 避免使用 |
|------|---------|---------|
| 文件搜索 | `Glob` | `find` / `ls -R` |
| 内容搜索 | `Grep` | `grep` / `rg` |
| 读取文件 | `Read` | `cat` / `head` / `tail` |
| 编辑文件 | `Edit` | `sed` / `awk` |
| 写入文件 | `Write` | `echo >` / `cat <<EOF` |
| 代码探索 | `Agent(Explore)` | 多次串行 Grep |
| 并行任务 | 单消息多 tool call | 串行逐个执行 |

## Plan Mode 使用场景

**所有任务必须先 Plan Mode 规划再执行**，禁止跳过规划直接写代码：

- 涉及 3 个以上文件的跨模块变更
- 新功能实现（不确定架构方向）
- 重构（涉及移动/删除/合并文件）
- 用户需求模糊需要先澄清
- 单文件修改、Bug 修复等小任务同样需要（规模小可以简化计划，但不能跳过）

**计划文件末尾必须包含 `- [ ]` 核对清单**，覆盖所有实施步骤（含 DDL、测试、文档同步等非代码步骤）。声称完成前逐条勾选。

---

## 上下文节约

- 不要用 Read 重复读取刚编辑过的文件（编辑成功后内容已是最新）
- 不要用 Grep/Bash 验证刚完成的写入操作（Edit/Write 失败会直接报错）
- Agent 结果只需转述关键发现，不要逐字复制返回内容给用户
- 每次响应聚焦当前任务，不要附带无关的背景说明
