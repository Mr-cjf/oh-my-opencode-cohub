# 发版规范

> **规范源**: 团队约定（oh-my-opencode-cohub）
> **生效范围**: 所有版本发布

## 执行清单

- [ ] 发版前必须更新 `CHANGELOG.md`，按 Keep a Changelog 格式记录本次变更
- [ ] CHANGELOG 条目必须区分：新增 / 修复 / 变更 / 移除
- [ ] CHANGELOG 提交与版本号提交必须分开（先 docs: 再 chore:）
- [ ] 版本号遵循 SemVer：主版本.次版本.修订号
- [ ] `package.json` 中 `repository.url` 必须指向正确的 GitHub 仓库地址（CI 使用 `--provenance` 校验依赖此项）
- [ ] 推送 tag 前确认所有代码已提交并推送到 GitHub
- [ ] 每次发版后必须重新安装并重启 OpenCode 验证

---

## 发版流程

1. **更新 CHANGELOG.md** — 新增版本条目，填写改动内容
2. **提交 CHANGELOG** — `git add CHANGELOG.md && git commit -m "docs: 更新 CHANGELOG vX.Y.Z"`
3. **更新版本号并打 tag** — `npm version patch -m "chore: 版本号 %s"`（自动更新 package.json、创建 commit、打 tag）
4. **推送触发发布** — 确保使用 SSH remote（`git@github.com:...`），然后 `git push --follow-tags`（CI 自动构建并发布到 npm）
5. **重装验证** — `bunx oh-my-opencode-cohub install` + 重启 OpenCode

> 提示：步骤 3 中 `patch` 可替换为 `minor` 或 `major`，根据 SemVer 选择。

---

## CHANGELOG 格式

```markdown
## [版本号] - YYYY-MM-DD

### 新增
- 新功能描述

### 修复
- Bug 修复描述

### 变更
- 行为变更描述

### 移除
- 已删除的内容
```

## CR 检查清单

- [ ] CHANGELOG.md 是否在发版前更新？
- [ ] 版本号是否符合 SemVer？
- [ ] CHANGELOG 提交和版本号提交是否分开？
- [ ] 发版后是否重新安装验证？
