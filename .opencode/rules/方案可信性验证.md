## 执行清单

> 强制性规范。缺失任一项视为任务未完成。

- [ ] 方案中涉及 `@opencode-ai/*` SDK API 调用时，必须委派 @co-librarian 查阅 opencode 源码或官方文档确认 API 签名和用法
- [ ] 方案中涉及 opencode 配置项（`opencode.json`、插件系统、hook 机制等）时，必须查阅源码或文档确认其存在性和行为
- [ ] 方案中涉及 opencode 代理系统（subagent 类型、system prompt 注入方式、tool 权限等）时，必须查阅源码确认机制
- [ ] 不能仅凭推测或记忆制定方案——所有对 opencode 内部行为的假设必须标注出处（源码路径 / 文档链接）
- [ ] 方案中的关键结论必须在方案末尾标注验证来源（「已验证：`src/xxx.ts:42`」或「已确认：官方文档 xxx 章节」）

---

## 为什么需要这个规范

opencode 是一个快速迭代的项目，其内部 API 和行为可能在不同版本间变化。如果基于错误的行为假设制定方案，会导致执行失败、返工，浪费大量上下文和算力。

## 适用场景

以下情况**必须**委派确认，**禁止**直接基于假设输出方案：

| 场景 | 查阅对象 | 委派代理 |
|------|---------|---------|
| 使用 `@opencode-ai/plugin` SDK 注册代理/hook | 源码 `node_modules/@opencode-ai/*` 或官方文档 | @co-librarian |
| 修改 `opencode.json` 配置项 | 源码或 opencode 文档中的配置 schema | @co-librarian |
| 涉及 `experimental.*` 钩子（如 `chat.system.transform`） | 源码中对应 hook 的实现 | @co-librarian |
| 涉及子代理类型定义（`subagent_type`） | 源码或本项目 `AGENTS.md` 中已列明的代理列表 | @co-explorer / @co-librarian |
| 涉及 TUI 面板（`@opentui/*`） | 源码 `src/tui.ts` 或 `@opentui/*` 文档 | @co-explorer / @co-librarian |

## 排除场景

以下情况**不需要**验证，可直接基于已有知识制定方案：

- 修改本项目自身的业务逻辑代码（`src/` 下，非 opencode SDK 部分）
- TypeScript / ESM / Bun 等通用技术栈的使用（不依赖 opencode 特定行为）
- 已有明确项目规则的领域（如 Git 工作流、发版流程）
