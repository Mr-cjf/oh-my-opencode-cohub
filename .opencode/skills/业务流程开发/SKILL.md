# 场景 A：新增业务流程

新增一个完整的业务功能（如"分镜图生成""批量导入角色""语音设计"），不只是加一个接口，而是从需求到上线的完整链条。

### 阶段一：需求理解（动手前必须先搞清楚）

- [ ] **这个业务场景是什么？** 用户要完成什么任务？一句话说清楚
- [ ] **涉及哪些数据？** 需要新表还是复用现有表？数据从哪来、存哪去？
- [ ] **涉及哪些服务？** 只在当前模块？还是需要调其他服务（task/run/media/auth）？
- [ ] **需要几个接口？** 接口之间的调用顺序是什么？
- [ ] **是否需要前端配合？** 前端同学是否已知晓？有无对应的前端 PR？
- [ ] **参考现有实现？** 项目中是否已有类似的业务流程可以参照？

### 阶段二：数据模型设计（如果需要新表/字段）

参照 `docs/项目规则文档/数据库规范.md`：

- [ ] 先分析数据本质（文件地址？关联关系？统计？AI文本？），再设计表
- [ ] 禁止 JSON 列，对象数据拆类型列，列表数据评估后决定拆 1:N 或 TEXT
- [ ] 主键：高速表 `VARCHAR(191)`，低速表 `BIGINT AUTO_INCREMENT`
- [ ] 包含 `created_at` / `updated_at`，字段 COMMENT 写清业务含义
- [ ] 双文件同步：`init-auth-run-schema.sql` + `数据库表结构更新历史/` 版本化 SQL

### 阶段三：接口设计

- [ ] **列表出所有需要的接口**：方法 + 路径 + 用途
- [ ] **确定调用顺序**：哪个先调、哪个后调、哪些可并行
- [ ] **鉴权设计**：每个接口是否需要认证？`X-User-Id` 还是 `Authorization`？
- [ ] **SSE/流式判断**：是否有长时间处理需要 SSE 推送进度？
- [ ] **错误处理设计**：每种异常场景返回什么错误码？

### 阶段四：代码实现

**Controller 层**：
- [ ] `@RestController` + `@RequestMapping`，类放在 `controller/` 目录
- [ ] `userId` 从 `X-User-Id` 请求头取，**禁止放请求体**
- [ ] 参数校验失败 → `400 + 错误码`；权限失败 → `404`
- [ ] SSE 端点：`SseEmitter(0L)` + 心跳（15s）+ `onCompletion/onTimeout/onError` 清理

**Service 层**：
- [ ] 写操作加 `@Transactional`，注意自调用事务失效
- [ ] 服务间调用必须注册 `TraceIdRestTemplateInterceptor`

**DTO 层**：
- [ ] **强类型 DTO，禁止 `Map<String, Object>`**
- [ ] 请求 DTO 放在 `dto/api/`，命名 `XxxRequest` / `XxxResponse`

**网关配置** ⚠️ 最容易遗漏：
- [ ] 检查 `application.yml`，已有通配路由则无需新增
- [ ] `JwtAuthenticationFilter.isPublicPath()` 鉴权豁免同步更新
- [ ] 运行 `mvn -pl gateway -am clean package` 验证

### 阶段五：测试

- [ ] Controller 测试覆盖：200 / 401 / 404 / 400
- [ ] Service 测试覆盖核心业务逻辑 + 边界条件
- [ ] 业务流程联调：用真实数据走一遍完整调用链
- [ ] 运行 `mvn -pl {module} -am test` 全部通过

### 阶段六：文档同步

- [ ] **业务流程文档**：`docs/业务流程说明文档/<场景>.md` — 业务流程图 + 接口调用顺序 + 前端代码示例 + 注意事项
- [ ] **API 契约文档**：`docs/migrated-java-apis/<模块>.md` — 每个接口的请求/响应/错误码
- [ ] **前端联调指南**：SSE 事件处理、错误重试策略、边界条件
- [ ] 新建模块：`docs/migrated-java-apis/README.md` 追加条目

### 阶段七：CR 检查清单

- [ ] 需求理解是否到位？（数据来源、接口调用顺序是否合理）
- [ ] 数据模型是否符合规范？（无 JSON、COMMENT 清晰、主键策略正确）
- [ ] `userId` 取自请求头？权限失败返回 404？
- [ ] 网关路由已配置？SSE 有心跳和清理？
- [ ] DTO 强类型？测试覆盖认证失败和权限不足？
- [ ] 业务流程文档是否讲清了接口调用顺序？是否包含前端代码示例？

# 场景 B：调整已有业务流程

修改已有业务逻辑时（不只是改参数，而是改业务行为），按以下流程逐项完成。

### 第一步：变更影响分析

- [ ] **改了什么？** 是改接口参数/响应/鉴权/路径，还是改业务逻辑/数据流？
- [ ] **影响哪些上下游？** 哪些接口会被影响？哪些调用方需要同步更新？
- [ ] **影响哪些文档？** `migrated-java-apis/` + `business-process-description/` 哪些文档需要更新？

| 变更类型 | 影响范围 |
|---------|---------|
| 修改请求参数（新增/删除/改类型/改必填） | 调用方代码 + 测试 + 文档 |
| 修改响应结构（字段变更/新增错误码） | 前端 + 文档 |
| 修改业务逻辑（处理流程/状态机/校验规则） | 测试 + 业务流程文档 |
| 修改鉴权方式 | 网关 + 文档 |
| 接口路径变更 | 网关路由 + 所有调用方 + 文档 |
| 新增/修改 SSE 事件类型 | 前端 + 文档 |
| 需要新表/字段 | 数据库规范全部 checklist |

### 第二步：数据模型变更（如需要）

- [ ] 是否涉及 DDL？→ 双文件同步（`init-auth-run-schema.sql` + 版本化 SQL）
- [ ] DDL 先于代码在目标环境执行

### 第三步：代码变更

- [ ] **全局搜索调用点**：`grep -rn "被改的方法名\|被改的路径" --include="*.java"`
- [ ] **同步更新测试**：搜索测试中对该接口的 mock/verify
- [ ] **破坏性变更**（删除字段/改类型/改路径/改状态机）：MR 描述和文档中明确标注
- [ ] **编译验证**：`mvn -pl {module} -am test-compile`

### 第四步：网关检查

- [ ] 路径变更 → 更新路由；鉴权变更 → 更新 `JwtAuthenticationFilter.isPublicPath()`
- [ ] 运行 `mvn -pl gateway -am clean package`

### 第五步：测试更新

- [ ] 更新受影响的 Controller/Service 测试
- [ ] 新增错误码 → 补充对应测试 case
- [ ] 业务流程变更 → 更新联调测试
- [ ] 运行 `mvn -pl {module} -am test` 全部通过

### 第六步：文档同步 ⚠️ 最容易遗漏

- [ ] **业务流程文档**：更新流程图 + 接口调用顺序 + 前端代码示例
- [ ] **API 契约文档**：更新请求/响应示例、错误码
- [ ] 破坏性变更在文档中**明确标注**
- [ ] 跨服务接口：检查所有调用方文档是否需要同步更新

### 第七步：CR 检查清单（调整场景）

- [ ] 变更影响分析是否完整？（上下游、文档、网关）
- [ ] 所有调用点是否已搜索并同步更新？
- [ ] 测试是否同步更新并通过？
- [ ] `migrated-java-apis/` 文档是否已更新？
- [ ] `business-process-description/` 业务流程文档是否已更新？
- [ ] 破坏性变更是否在 MR 和文档中明确标注？
- [ ] 涉及 DDL？→ 双文件同步是否完成？

> 违反第4-5条（文档未更新），CR 直接拒绝。

## 常见错误模式

| 错误 | 正确做法 |
|------|---------|
| 一上来就写代码，不分析数据和接口设计 | 先走阶段一（需求理解），设计数据模型和接口列表 |
| `userId` 放在请求体 | 从 `X-User-Id` 请求头取 |
| 权限不足返回 403 | 返回 404（不泄露资源是否存在） |
| 忘记配置网关路由 | 先检查通配路由是否已覆盖 |
| `Map<String, Object>` 返回值 | 定义强类型 DTO |
| 改参数不改文档 | `migrated-java-apis/` 和 `business-process-description/` 两处同步 |
| 破坏性变更不通知前端 | MR 描述 + 文档中明确标注 |
| 新增表/字段不走数据库规范 | 参照 `database-change` Skill 完成双文件同步 |
| 加接口不画业务流程图 | 前端和后来者看不懂接口间的调用关系 |
